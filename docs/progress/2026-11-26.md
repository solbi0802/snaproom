# 2026-11-26 — 프로젝트 기반 구성

## 이번 작업 범위

- React·TypeScript·Vite, CSS Modules 구성.
- ESLint·Vitest·Playwright와 CI 검사 설정.
- 업로드 시작 화면과 샘플·로컬 파일 썸네일의 기본 흐름.
- Vercel 빌드 설정과 로컬 지침 파일의 Git·배포 제외.

## 선택한 설계

- 도메인 검사 로직은 React 컴포넌트에서 분리한다.
- 이미지 URL은 로컬 자산 참조로 관리한다. 제거·초기화·언마운트 시 해제한다.
- 서버 통신과 편집 이력은 아직 추가하지 않는다. 업로드 흐름을 먼저 완성한 뒤 문서 상태로 확장한다.
- TypeScript 7 대신 현재 typescript-eslint의 지원 범위에 맞는 6.0 계열을 사용한다.

## 다음 시작 행동

파일 디코딩이 끝난 뒤 목록에 반영되는 준비 상태를 만들고, 사진 교체·순서 변경과 드롭 오류 흐름을 완성한다.

## 검증 결과

- TypeScript, ESLint, Vitest(4개), 프로덕션 빌드 검사 모두 통과.
- Playwright: 데스크톱·모바일 Chromium에서 총 6개 통과. 샘플 선택·제거·초기화, 잘못된 파일 선택 시 기존 상태 유지, 실제 로컬 PNG 표시·제거 확인.
- 작은 화면에서 수평 넘침이 없는지 확인.
- AGENT.md는 Git 추적 대상이 아니며 .gitignore와 .vercelignore에서 제외.
- Vercel 빌드 설정 준비 후 사용자가 직접 배포했다고 알려줌. 이번 작업에서는 배포 주소·원격 결과를 별도 검증하지 않음.
- GitHub Actions는 로컬 설정만 완료했으며 원격 실행은 아직 확인하지 않음.

## UI 방향 변경

- 사용자 요청: Figma처럼 컴팩트하고 깔끔한 상용 작업 도구 스타일.
- 중립적인 작업 영역, 얇은 구분선, 파일·안내 패널, 작은 헤더와 컨트롤로 구성.
- 장식적인 영문 슬로건과 큰 제목·여백을 정리하고 강조색은 주요 동작·포커스에 제한.
