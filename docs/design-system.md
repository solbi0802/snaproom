# Snaproom UI/UX 기준

새 화면·기능을 작업할 때 이 문서와 `src/shared/styles/tokens.css`, `src/shared/ui/`를 먼저 확인한다. 현재 구현에서 반복되는 요소만 공통화하며 별도 컴포넌트 라이브러리나 Storybook 구축은 MVP 이후 필요할 때 검토한다.

## 제품의 시각 언어

**사진이 중심인, 조용하고 컴팩트한 편집기.** 사진 선택 → 편집 → 저장의 짧은 흐름을 유지한다.

- 흰 패널, 옅은 회녹색 작업 영역, 선명한 잉크색 본문, 1px 구분선.
- Snaproom의 강조색은 evergreen 청록색 `accent`다. 주요 동작·선택·드롭 상태·포커스에 사용한다.
- 로고 마크는 사진 프레임의 네 모서리를 표현한다. 상태 단계는 작은 번호 타일과 한글 라벨로 표현한다.
- 사진 콘텐츠와 스티커가 시각적인 중심이다. UI 자체의 다채로운 장식·큰 배너·영문 슬로건은 추가하지 않는다.
- 패널을 채우기 위한 가짜 메뉴·동작하지 않는 도구·실체 없는 수치는 만들지 않는다.

## 참고와 구분 원칙

컴팩트한 컨트롤, 작업 영역과 보조 패널의 분리, 명확한 선택·포커스 같은 일반적인 사용성 원칙을 참고한다. 특정 제품의 화면을 픽셀 단위로 복제하지 않는다.

Snaproom의 로고·명칭·청록색 강조·사진 중심 정보 구조·선택/편집/저장의 흐름을 유지한다. 다른 제품의 로고, 아이콘 파일, 스크린샷, 고유 문구를 가져오거나 자사와 제휴한 것처럼 표시하지 않는다. 에셋은 직접 제작하거나 사용 권한을 확인한 것을 사용한다.

## 토큰 — 시각 기준의 원본

`src/shared/styles/tokens.css`의 `--sr-*` 토큰을 사용한다. 기능 CSS에서 새로운 색상·글자 크기·버튼 모양을 임의로 추가하지 않는다.

| 영역   | 사용 기준                                                                         |
| ------ | --------------------------------------------------------------------------------- |
| 색상   | surface, workspace, text, muted, border, accent, danger 등 역할 토큰              |
| 본문   | body 13px, label 12px, caption 11px, title 20px. rem 단위로 사용자 글꼴 설정 반영 |
| 간격   | 4·8·12·16·20·24·32·40·48px                                                        |
| 모서리 | 작은 요소 4px, 컨트롤 6px, 패널 8px                                               |
| 밀도   | 데스크톱 컨트롤 높이 32px, 헤더 48px, 패널 헤더 44px                              |
| 터치   | 모바일·거친 포인터에서 주요 컨트롤 최소 44px                                      |
| 패널   | 기본 왼쪽 216px / 오른쪽 224px. 중앙 작업 영역은 남은 너비 사용                   |
| 아이콘 | 공통 Icon 사용, 기본 16px. 빈 상태의 이미지 표시는 32px                           |

보더·포커스·에러 등의 색은 의미를 유지한다. disabled는 제한 상태이며 중요 정보를 흐리게 만드는 용도로 쓰지 않는다. 사진 자체의 색상과 사용자가 고른 출력 배경색은 UI 팔레트와 구분한다.

토큰 변경은 앱 전체 변경이다. 한 화면만 보고 값을 바꾸지 말고 빈 화면·사진 선택 후·오류·모바일 상태를 함께 확인한다. 새 시각 역할이 필요하면 기존 토큰 재사용 가능성을 확인한 뒤 의미 있는 이름으로 추가한다.

## 공통 컴포넌트

| 컴포넌트      | 용도                            | 지킬 규칙                                                     |
| ------------- | ------------------------------- | ------------------------------------------------------------- |
| Button        | primary / secondary / ghost     | 스타일은 공통 CSS에서 관리, 화면에서는 위치·폭·마진만 지정    |
| IconButton    | 사진 제거 등 아이콘 동작        | label 필수, 접근 가능한 이름 제공                             |
| PanelHeader   | 파일·설정·저장 패널 제목과 개수 | 동일 높이·글꼴·구분선 사용                                    |
| WorkflowSteps | 사진 선택·편집·저장 현재 단계   | current로 지정, 이동 기능 없이 클릭 가능한 것처럼 꾸미지 않음 |
| Notice        | 오류 메시지                     | 무엇이 문제인지와 다음 행동을 표시, role=alert                |
| Icon          | 제품의 작은 선형 아이콘         | 이름으로 사용, 장식 아이콘은 스크린리더에서 제외              |

```tsx
import { Button, IconButton } from '../../shared/ui/Button'
import { Icon } from '../../shared/ui/Icon'

<Button variant="primary" onClick={handleExport}>PNG 저장</Button>
<IconButton label="선택한 스티커 삭제" onClick={handleDelete}>
  <Icon name="close" />
</IconButton>
```

입력·팝오버·대화상자는 실제로 필요해질 때 같은 토큰과 상호작용 규칙으로 추가한다. 아직 사용하지 않는 범용 컴포넌트를 미리 대량 제작하지 않는다.

## UX 동작 규칙

- **한 구역의 주요 동작은 하나:** primary를 여러 개 나란히 두지 않는다. 보조 동작은 secondary 또는 ghost.
- **라벨은 행동으로:** 사진 선택, 사진 추가, PNG 저장, 삭제처럼 결과가 예상되는 짧은 한글을 사용한다.
- **상태 보존:** 뒤로 가기·패널 전환으로 편집을 초기화하지 않는다. 실제 삭제·초기화의 영향은 명확히 한다.
- **파일 오류:** 기존 정상 사진을 유지하고 원인과 해결 행동을 알려준다. 초과 파일을 조용히 버리지 않는다.
- **처리 중:** 중복 요청을 막고 처리 상태를 알린다. 다운로드 요청과 실제 저장 완료를 혼동하지 않는다.
- **드래그와 대체 조작:** 선택 상태를 보여주고 키보드로 사용할 수 있는 위치·크기·삭제 조작도 제공한다.
- **일관된 피드백:** 오류는 Notice, 일반 처리 안내는 status/live 영역, 현재 단계는 WorkflowSteps로 표현한다.
- **툴팁에 필수 정보 숨기지 않기:** 터치와 키보드에서도 주요 동작과 안내를 사용할 수 있어야 한다.

## 반응형과 접근성

- 1120px 이하에서는 오른쪽의 보조 안내 패널을 축소한다. 680px 이하에서는 파일 사이드바를 접고 중앙 작업을 우선한다.
- 현재 오른쪽 패널은 보조 안내만 담고 있다. 향후 편집 컨트롤이 들어가면 숨기기 전에 모바일용 접근 경로를 반드시 제공한다.
- 최소 320px에서 수평 넘침·텍스트 겹침을 확인한다. 파일명은 축약해도 버튼의 접근 가능한 이름에는 전체 이름을 사용한다.
- 인터랙티브 요소는 네이티브 button·input을 기반으로 한다. focus-visible을 제거하지 않는다.
- 선택·오류를 색만으로 표현하지 않고 텍스트·라벨·aria 상태를 함께 사용한다.
- 모션은 상태 전환을 돕는 짧은 변화로 한정하며 prefers-reduced-motion을 존중한다.

## 이후 UI 작업 절차

1. 이 문서, 토큰, 이미 있는 공통 컴포넌트를 먼저 읽는다.
2. 기존 컴포넌트와 토큰으로 구현한다. 공통 컨트롤의 appearance를 기능 CSS에서 덮어쓰지 않는다.
3. 새 패턴은 사용 목적·상태·모바일 동작을 정하고 필요한 최소 크기로 추가한다.
4. 아래 확인 목록과 검사 결과를 남긴다.

- [ ] 기존 색상·글꼴·간격·버튼 기준을 재사용했는가?
- [ ] 빈 상태·정상 상태·disabled·오류·처리 중을 필요한 범위에서 확인했는가?
- [ ] 모바일·키보드·포커스·터치 대체 조작이 가능한가?
- [ ] 현재 작업 상태가 화면 전환 후 유지되는가?
- [ ] 사진 자체보다 UI 장식이 더 튀지 않는가?
- [ ] 새 규칙이 생겼다면 이 문서와 공통 코드에 반영했는가?

`npm run check:ui`는 토큰 파일 밖의 CSS hex 색상과 공통 UI 밖의 직접 button 사용을 검사한다. `npm run check`와 CI에 포함된다. 이 검사는 간단한 가드이며 사용성·시각 품질·모든 CSS 우회 사용까지 자동 보장하지는 않는다. 인터랙션을 변경하면 기존 브라우저 테스트를 실행하고 데스크톱·모바일 화면도 확인한다.
